# How Elasticsearch Reads Data

```
GET /products/_doc/100
           |
           |         { "name": "Coffee Maker" }
           v        /
        [Node X]   /
  (coordinating node)
           |
           |
           v
     [Rep Group B]           Routing
           |
           |
           v
      [Replica B1]      Adaptive replica selection
           |
           |
           v
    +----------------------------------------+
    | [Primary] [Replica] [Replica] [Replica] |
    | [Shard B] [   B1  ] [   B2  ] [   B3  ] |
    +----------------------------------------+
                 Replication group B
```

1. A given node receives a read request. This is called the `coordinating node`
   - This involves figuring on which shard the document is stored, via routing.
   - This often yields the primary shard
2. ES then uses _Adaptive replica selection_ formula to select a replica that can be used for the read operation.
3. The coordinating node then requests data from the selected replica
4. Once a response is ready, the coordinating node returns the response to the caller
