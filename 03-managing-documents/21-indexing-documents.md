# Indexing Documents

- Let's add documents
- In ES, we say it like this: `Let's index documents`:
- Run

```
POST /products/_doc
{
    "name": "Coffeee Maker",
    "price": 64,
    "in_stock": 10
}
```

- Output:

```json
{
  "_index": "products",
  "_id": "nrr9T50Bv160fQzNvU9C",
  "_version": 1,
  "result": "created",
  "_shards": {
    "total": 3,
    "successful": 3,
    "failed": 0
  },
  "_seq_no": 0,
  "_primary_term": 1
}
```

- `_shards` tells us how many shards succeeded/failed to store our document.
  - Ours has been replicated to 3 shards: 1 primary shards, 2 replica shards.
- the `_id` specifies the identifier for the document. We din't specify one, so it was autogenerated.

To index a document with a specific ID, we use the PUT verb

- `action.auto_create_index`: If enabled, indices will automatically be created when adding documents
- If we add a document to a non-existing index, the index will be auto-created for us, then the document will be added to it.
- It is best practice though to create indices in advance before adding documents to them.
- Run:

```
PUT /products/_doc/100
{
    "name": "Toaster",
    "price": 49,
    "in_stock": 4
}
```

- Output:

```json
{
  "_index": "products",
  "_id": "100",
  "_version": 1,
  "result": "created",
  "_shards": {
    "total": 3,
    "successful": 3,
    "failed": 0
  },
  "_seq_no": 0,
  "_primary_term": 1
}
```

- Note that the ID is a string, and doesn't have to be an integer
